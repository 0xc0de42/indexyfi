# IndexFi Flap contracts V3 — current signed-price API

## Scope / installation
Overlay on `indexfi-fe-contracts-be-2026-11-26.zip` (the `indexfi/` repository root) and replace the V2 Flap files. No changes to the existing OpenFour financial contracts, Python backend or frontend. This is not an audited or deployed release. The attached `contracts.zip` is the earlier Hardhat dependency baseline; the financial source baseline is the newly uploaded November 26 snapshot plus the Flap V2 overlay.

```sh
cd contracts/openfour
npm ci
node scripts/compile-flap-selected.cjs
npx hardhat test --config hardhat.flap.config.js --no-compile test/IndexFi.flap.test.js
```

## Architecture
- `IndexFiFlapFactory`: current IndexFi factory entrypoints plus Flap launcher factory (`lf-v1`). Creates a native vault factory in its constructor, with the reverse binding immutable. Deploy `IndexFiFlapVault` implementation first and pass its reviewed address as `Config.vaultImplementation` (deployment constructor only; prevents exceeding the initcode size limit). Creator-funded atomic launch; no fundraising.
- `IndexFiFlapLauncher`: registered by `Portal.newLauncher`; only the IndexFi factory may execute the launch; `launchTaxTokenV2` uses `VAULT`, zero strategy (resolved by Portal), exact reserve and a 100% VAULT fee slot.
- `IndexFiFlapVaultFactory`: `pl-v1`. The factory prepares a clone before launch because realized collateral value is required for exact backing and the initial ratio; the Portal's `newVault(predictedToken, launcher, kind, launchParams)` claims that clone, checks the exact raw launch hash and reserve distribution, binds the predicted token without calling it, and returns the vault as the native fee recipient. The preparation and callback occur in the same atomic creation transaction. Both factories are mutually bound. This is a deliberate deviation from clone deployment inside `newVault` itself and needs sponsor review.
- `IndexFiFlapVault`: same financial entrypoints, native vault description/schema and strategy callback. Reserved tokens are held in the vault's own Token Dock account. Exact balance checks reject unexpected primary transfer taxes. The creator receives issued shares less pool shares. Initial LP is burned. Upgrades are deliberately disabled even for Guardian (immutable logic); Guardian is the only caller admitted to the upgrade entrypoint. No collateral admin withdrawal.

## Compatibility with the November 26 source snapshot
The existing `IIndexFiFactory.sol` / `IIndexFiVault` definitions (both in `contracts/interfaces/IIndexFi.sol`) are not modified. The provider-facing shared ABI matches current OpenFour, not the old V5 ABI. `createVault` now takes `requestId` first; `VaultCreated` indexes it. Successful requests are marked in `usedRequestIds` and vaults in `isVault`; failures roll back both. `buildCreateArgs` returns opaque Flap-specific encoded request data, not signed OpenFour Core args; it is not a Flap authorization digest. The FE must branch before the OpenFour signer flow and supply `launchAuthorization = abi.encode(bytes32 salt)` with a provider-specific request ID. The current Flap path accepts no native fee; actual Portal salt locking/fee handling is **not implemented or verified**, and is a release gate.

All six current price wrapper entrypoints are present: `quoteCreateWithPrices`, `createVaultWithPrices`, `quoteDepositWithPrices`, `depositWithPrices`, `redeemWithPrices`, and `redeemInKindWithPrices`. Each accepts up to four matched payload/signature pairs, forwarding each to `IIndexFiOracle.updatePrices`. The bound oracle authenticates, validates feed mapping and timestamps; the wrappers do not trust arbitrary unsigned frontend values. Empty arrays post nothing, same as OpenFour. Quote wrappers must use `eth_call`/simulateContract (a transaction would persist oracle updates). The execution wrappers hold the reentrancy guard over price updates and financial execution. Internal calls preserve the original wallet as `msg.sender`; any revert rolls back both the oracle updates and the financial action.

The supplied snapshot lacks `AtlasSignedOracle.sol` (referenced in `test/IndexFi.withPrices.test.js` under the absent `dump/preset-ready`). Its `AtlasPushOracle.updatePrices` intentionally ignores payloads. Do not deploy the test-only `MockSignedFlapOracle`: it verifies ECDSA signatures over a custom, domain-bound fixture format, not Atlas's actual wire format. Obtain and review the genuine signed oracle implementation; deploy a new instance with Flap USD and correct test-constituent/feed bindings. Deploy or configure a Flap USD-compatible basket adapter with verified routes. The existing deployed OpenFour quote is a different ERC-20, so its immutable settlement bindings cannot be reused unchanged. Do not assume all 66 reference assets have executable testnet routes.

`redeem(shares,minNetUSDT,minAssetOut[],deadline)` replaces the old 3-argument signature and `redeemWithMinimums` is superseded. `previewRedeemAssets` returns amounts and expected quote for each leg. `previewRedeemInKind` returns gross, fee, net arrays; `redeemInKind` returns net and fee arrays and emits `RedeemedAsset` for every leg plus the current two-argument `RedeemedInKind` event. Like the latest OpenFour contract, zero minimums are accepted (unsafe if used on nonzero swaps); the frontend must supply meaningful per-leg and aggregate floors. Both ordinary redemption paths remain oracle-independent; if optional price posting fails, use the ordinary methods. `phase()` remains Migrated for a DEX-tradable portfolio; it is not Flap graduation status. `forwardTaxRevenue()` remains additive and transfers only unaccounted settlement surplus to the creator.

Frontend integration is not included in this overlay. It must use a provider-aware deployment manifest, Flap settlement, correct asset mapping, salt authorization rather than OpenFour signature, and tax-aware secondary trading. Keep the shared price delivery endpoint. No Python changes.

## Financial safety
- Existing production `AtlasPushOracle` checks source/updated timestamps, feed validity and per-feed maximum age. The V3 vault calls the bound oracle during creation/issuance. Mock oracle tests are not evidence for real Atlas feeds.
- On creation and issuance, a one-unit settlement bid/ask probe must be within 5% of Atlas valuation. This is a conservative MVP guard and does not establish manipulation resistance, a TWAP, minimum market depth or a deposit rate limit. Threshold and probe size are engineering defaults requiring review. Per-leg and aggregate limits, actual received balance accounting and atomic rollback are retained.
- In-kind redemption avoids swap-route failure, but cannot make a frozen or fee-on-transfer constituent transferable. Fixed supply is never minted or burned by IndexFi; returned shares replenish inventory. Locked LP shares remain economically outstanding. Tax fee forwarding does not alter backing.
